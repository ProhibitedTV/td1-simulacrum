# TD-1 Simulacrum audit — 2026-09

## Scope

This audit was performed after the v0.21 live-debugger merge. It reviewed the current CI result, core machine/trace/debug paths, persisted state contracts, parity/wire code, serial tests, browser-player configuration parsing, and project quality configuration.

The goal was not to redesign TD-1. The goal was to find places where a green test suite could still hide ambiguity or weak validation before physical bench work begins.

## Baseline observed

The v0.21 `main` quality workflow was green across Ruff, the Relic-player JavaScript syntax gate, and Python 3.11/3.12/3.13. The Python 3.11 run reported 172 passing tests and approximately 77% aggregate coverage.

One Python warning was present despite the green run: `tests/test_serial_adapter.py` used a non-raw regular-expression string containing `\[`, producing an `invalid escape sequence` deprecation warning.

## Finding A — warning-clean CI was not enforced

Severity: low, but important for a pre-hardware quality gate.

Pytest did not treat warnings as errors, so a newly introduced warning could remain indefinitely while every matrix job stayed green.

### v0.22 remediation

- fix the known invalid-escape warning;
- configure pytest with `filterwarnings = ["error"]`;
- require the existing Python matrix to remain green with that stricter policy.

## Finding B — canonical envelope bytes could hide non-canonical nested parity values

Severity: high at the live hardware boundary.

Wire v1 already rejected non-canonical JSON serialization for the outer `td1.parity-wire` envelope. However, nested `ParityCapabilities`, `ParityRequest`, and `ParityResponse` loaders use typed construction that can normalize input through integer/string conversion, defaults, sorting, or deduplication.

A frame could therefore be byte-canonical JSON while carrying a nested value such as `"sequence":"0"`. The old path could parse that string into integer `0` and continue as though the sender had emitted the canonical schema.

That weakens the meaning of a transport transcript: the exact bytes would be preserved, but successful interpretation could depend on receiver coercion.

### v0.22 remediation

At the wire boundary, parse the nested parity object and require its canonical `as_dict()` representation to reproduce the received payload exactly, including JSON scalar types and list contents/order.

This rejects:

- numeric strings used where integers are required;
- booleans used as integers;
- omitted canonical default fields;
- duplicate or non-canonical capability lists that would otherwise normalize;
- other payload drift hidden by typed parsing.

Wire schema v1 does not change. Canonical senders are unaffected.

See `PARITY_WIRE.md` and ADR 0022.

## Finding C — broader saved-artifact loaders still use coercive parsing

Severity: medium; follow-up recommended.

The audit found older offline/persisted artifact loaders that use patterns such as `int(...)`, `str(...)`, or `bool(...)` directly on JSON values. Examples include portions of render-state, trace/event, debugger, parity-report, and Relic-player artifact parsing.

This does not imply that the artifacts are presently producing incorrect machine states: many layers subsequently verify digests or derived invariants. It does mean the parser boundary is less strict than the newer `td1.machine-state` loader, which uses exact JSON type checks before construction.

### Recommended follow-up

Perform a separate compatibility-conscious pass that:

1. inventories every versioned `from_dict()` / `from_json()` loader;
2. distinguishes strict canonical artifact schemas from intentionally permissive human-input surfaces;
3. replaces coercive parsing in canonical persisted artifacts with exact type requirements;
4. validates redundant fields rather than silently ignoring or regenerating them;
5. adds mutation tests for booleans-as-integers, numeric strings, missing fields, extra/default fields, and list normalization;
6. preserves existing canonical fixture bytes and digests unless a schema-version change is explicitly justified.

Do not mix that broader pass with physical instruction encoding.

## Finding D — RenderState redundant-field validation deserves a focused review

Severity: medium; deferred.

`td1.render-state` contains redundant/presentation-contract information in addition to machine truth. Its loader already restores the machine and verifies the complete machine digest, which is strong. The audit nevertheless identified fields whose serialized representation should be reviewed for stricter load-time consistency, including active `planes`, semantic-weave version metadata, and exact scalar JSON types.

This is primarily artifact-integrity hardening, not a known arithmetic bug.

## Finding E — CI action-runtime deprecation notices

Severity: infrastructure maintenance.

GitHub-hosted runners currently report that some pinned action major versions target Node 20 and are being forced onto Node 24. The project runtime itself is not using Node 20; the warning comes from action implementation versions such as checkout/setup actions.

Do not blindly bump action majors without reviewing the current upstream action releases and migration notes. Track this as CI-maintenance debt rather than weakening the test gate.

## What the audit did not change

The audit does not change:

- balanced-ternary arithmetic;
- logical ISA semantics;
- machine-state authority;
- debugger stop semantics;
- parity expected-value semantics;
- wire schema version;
- electrical thresholds;
- physical hardware claims;
- the deferred 12-trit physical instruction/program-image encoding in Issue #2.

## Engineering conclusion

The v0.21 codebase was not in a broken state: its complete CI matrix was green and the reference execution layers remained internally consistent. The most consequential audit issue was subtler: **canonical bytes at a future hardware boundary must not depend on permissive receiver coercion to become a valid protocol object.**

v0.22 addresses that boundary first and turns warnings into test failures. The next audit-hardening pass should apply the same strictness discipline to offline versioned artifacts while preserving their existing canonical forms.
